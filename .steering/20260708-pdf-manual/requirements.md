# 要求内容

## 概要

PDF形式の製品マニュアルをRAGに取り込み、マニュアルに記載のある質問にも正確に回答できるようにする（設計書 D-003）。

## 背景

現在はメール（.eml / テキスト）由来の過去対応履歴のみを参照して回答を生成している。製品マニュアルの内容は参照できないため、「仕様・操作手順」に関する質問へ正確に答えられない。マニュアル（PDF）をRAGに取り込むことで、履歴に存在しない仕様質問にも回答できるようにする。

## 実装対象の機能

### 1. PDFテキスト抽出（etl/pdf_reader.py 新規）
- PyMuPDF（pymupdf）でPDFからページ単位でテキストを抽出する
- 空白ページはスキップする
- ヘッダー・フッター（ページ番号等）を簡易的に除去する
- 複数PDFの一括処理に対応する

### 2. マニュアル専用コレクションへの登録（index_service.py 更新）
- 既存 `support_emails` とは別の `product_manuals` コレクションに登録する
- メタデータに source=pdf_manual / file_name / page / date を付与する
- ページ境界をまたぐチャンクはページ番号を範囲（例: "12-13"）で記録する

### 3. 複数コレクション横断検索（query_service.py 更新）
- 回答生成時に emails / manuals 両コレクションを検索し、結果をマージして上位K件を使用する

### 4. CLI拡張（main.py 更新）
- `register --pdf <path>` で単一PDF登録
- `register --pdf-dir <dir>` でディレクトリ内の全PDF一括登録

### 5. 参照元表示の拡張（main.py 更新）
- 回答結果に、参照したマニュアルのファイル名・ページ番号を表示する（📄 file.pdf (p.23)）

## 受け入れ条件

### PDFテキスト抽出
- [ ] テスト用PDFからページ単位でテキストが抽出できる
- [ ] 空白ページがスキップされる
- [ ] 存在しない／不正なPDFでクラッシュせず空リストまたはNoneを返す

### マニュアルコレクション登録
- [ ] `register --pdf` でPDFが product_manuals コレクションに登録される
- [ ] メタデータに file_name / page が付与される
- [ ] PIIマスキングが通過している（既存 register 経路と同じ）

### 横断検索
- [ ] 回答生成時に emails と manuals 両方が検索対象になる
- [ ] 参照元にマニュアルのファイル名・ページが表示される

### 品質
- [ ] 既存テストを含め pytest が全てパスする
- [ ] ruff check がパスする

## 成功指標

- マニュアルにのみ記載のある内容について、参照元にPDFを提示した回答が生成できる

## スコープ外

以下はこのフェーズでは実装しない（設計書 D-003 スコープ外に準拠）：

- PDF内の画像・図表の解析
- OCR（スキャンPDF）
- Word / HTML 形式のマニュアル
