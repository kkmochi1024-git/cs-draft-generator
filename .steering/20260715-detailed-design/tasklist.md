# タスクリスト

## タスク完全完了の原則

**このファイルの全タスクが完了するまで作業を継続すること**

### 必須ルール
- **全てのタスクを `[x]` にすること**
- 「時間の都合により別タスクとして実施予定」は禁止
- 「実装が複雑すぎるため後回し」は禁止
- 未完了タスク `[ ]` を残したまま作業を終了しない

### タスクスキップが許可される唯一のケース
以下の技術的理由に該当する場合のみスキップ可能：
- 実装方針の変更により、機能自体が不要になった
- アーキテクチャ変更により、別の実装方法に置き換わった
- 依存関係の変更により、タスクが実行不可能になった

スキップ時は必ず理由を明記：
```markdown
- [x] ~~タスク名~~（実装方針変更により不要: 具体的な技術的理由）
```

### 学んだこと

**技術的な学び**:
- ドキュメントレビュー（doc-reviewer）がコード突き合わせで実装バグを発見することがある（`_map_ner_to_original` の同一固有表現重複時のマスク漏れ）。「実装どおりに書く」制約が逆に実装の欠陥を露出させる効果があった
- 「あるべき姿」を含む既存仕様書（glossary・functional-design・repository-structure）と実装の乖離が4件見つかった。スナップショット型ドキュメントは乖離検出器として機能する

**プロセス上の改善点**:
- worker への委譲時に design.md へ骨子・記載ルールを書き切ったことで、初版の精度が高く（レビュー6件全てで「実装との乖離ゼロ」評価）、差し戻しが発生しなかった
- 並列サブエージェントはセッション制限で部分失敗しうるため、失敗分の再実行を前提とした進行（完了分の指摘反映を先行）が有効だった
