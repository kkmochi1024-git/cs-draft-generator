# 要求内容

## 概要

フェーズ4まで（D-001 プロトタイプ〜D-004 WebUI）実装済みの現行コードベースを対象に、**コードの内容・処理の流れが読み取れるレベルの詳細設計書**を作成する。

## 背景

- 既存の設計書は「フェーズ別の変更設計」（phases/01〜04）と「マスター仕様書」（PRD・機能設計・アーキテクチャ等）に分かれており、**現時点の実装全体を横断的に説明するドキュメントが存在しない**
- フェーズ別設計書は各フェーズの差分を記述したものであり、現在のコード全体像を知るには複数ドキュメントとコードを行き来する必要がある
- 詳細設計書を読むだけで「どのモジュールに何があり、処理がどう流れるか」を理解できる状態にし、保守・機能追加・引き継ぎを容易にする

## 実装対象の機能（成果物）

### 1. 詳細設計書 `settings/detailed-design/`（新規フォルダ・モジュール別分割）

- 現行実装（D-001〜D-004 相当）の全モジュールを対象とする
- **settings/ 直下の新フォルダとする**（2026-07-15 ユーザー決定。phases/ は「各フェーズの差分」の凍結された履歴であるのに対し、本設計書は実装の進行に合わせて更新され続ける「現状スナップショット」でありライフサイクルが異なるため。phases/ の90番台規則は単一ファイル `{番号}-{概要}.md` 想定でありフォルダ構成には合わない点も理由）
- **モジュール別の分割構成**（2026-07-15 ユーザー決定。単一ファイルは情報量が多く読みにくいため。フェーズ別分割は既存 phases/01〜04 と軸が重複し、1モジュールの記述が複数ファイルに散るため不採用）：
  - `README.md` - 位置づけ・全体構成図・モジュール間シーケンス図・テスト構成
  - `01-masking.md` - PIIマスキング
  - `02-rag.md` - RAGパイプライン
  - `03-etl.md` - データ取り込み（eml/PDF）
  - `04-cli.md` - CLI（main.py・config.py）
  - `05-webui.md` - WebUI（app/）
- 記載内容：
  - モジュール構成と依存関係（Mermaid 図）
  - 各モジュールの全公開クラス・関数の責務・入出力・処理内容
  - 主要ユースケース（データ登録・回答生成）のシーケンス図・フローチャート（Mermaid）
  - 設定値（config.py・環境変数）の一覧
  - データモデル（Entity, MaskingResult, RegisterResult, AnswerResult 等）の定義
  - テスト構成の概要

### 2. `settings/INDEX.md` の更新

- 設計書一覧に詳細設計書の行を追加（リンク先は `detailed-design/README.md`。フェーズ別設計書ではないため ID はマスター仕様書と同様「-」とし、フェーズ列も「-」とする）
- INDEX.md の冒頭説明に「実装スナップショットの詳細設計書は `detailed-design/` 配下」の1行を追記

### 3. `settings/repository-structure.md` の更新（軽微）

- ディレクトリ構造ツリーの settings/ 配下に `detailed-design/` を1ブロック追記（成果物の置き場所を構造定義書に反映するため）

## 受け入れ条件

### 詳細設計書
- [ ] `src/` 配下の全モジュール（config, main, masking, rag, etl, app）が網羅されている
- [ ] 各ファイルが150〜300行程度に収まり、README から各モジュールファイルへ相互リンクされている
- [ ] 全公開クラス・公開関数（`_` 始まりでないもの）が記載され、責務・入出力が説明されている。内部関数も処理の流れの理解に必要なものは記載する
- [ ] データ登録フロー・回答生成フロー（CLI/WebUI 双方）が Mermaid 図で表現されている
- [ ] 記載内容が実装コードと矛盾しない（クラス名・関数名・処理順序・コレクション名・設定値をコードと突き合わせて検証済み）
- [ ] 未実装フェーズ（D-005 Zendesk 連携・D-006 LLM切替の未実装部分）は対象外であることが明記されている
- [ ] `/review-doc`（doc-reviewer 採点方式）のレビューを通過し、指摘事項を修正済み

### INDEX.md・repository-structure.md
- [ ] INDEX.md に詳細設計書の行が追加され、リンク・ステータス・最終更新日が正しい
- [ ] repository-structure.md のツリーに detailed-design/ が反映されている

## 成功指標

- 詳細設計書のみを読んで（コードを開かずに）、各処理の流れと担当モジュールを説明できる
- 新規参画者がコードリーディングの前に読む「1次資料」として機能する

## スコープ外

以下はこの作業では実施しない：

- ソースコードの変更・リファクタリング
- 未実装機能（D-005 Zendesk 連携、D-006 LLMバックエンド切替）の設計記述
- 既存マスター仕様書（architecture.md・functional-design.md 等）の内容改訂（ただし INDEX.md への行追加と repository-structure.md への detailed-design/ 追記は成果物登録として実施する）
- フェーズ別設計書（phases/01〜04）の改訂
