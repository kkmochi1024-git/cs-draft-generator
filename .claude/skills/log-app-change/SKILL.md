## 問い合わせアプリの変更履歴を記録する。TRIGGER: chatbot プロジェクトのコード・設定・設計書を変更したとき自動実行する。SKIP: ~/.claude/ 配下のカスタム資材変更のとき（→ /log-global-change を使う）

## 実行手順

1. このスキルディレクトリ内の `template.md` を読み込む

2. 以下の情報を会話の文脈から自動抽出する（不明な場合のみユーザーに質問する）：
   - **変更対象ファイル**: 変更したファイルのパス（複数可）
   - **変更種別**: 新規作成 / 更新 / 削除 / リファクタリング
   - **変更カテゴリ**: 機能追加 / バグ修正 / 設計変更 / 設定変更 / ドキュメント更新
   - **変更理由**: なぜ変更したか
   - **変更前の内容**: 主要な差分の要点（新規作成の場合は「新規作成のため該当なし」）
   - **変更後の内容**: 変更後の内容の要点
   - **影響範囲**: 影響するモジュール・機能・動作

3. プロジェクトディレクトリ内に `docs-ignore/changelog/` がなければ作成する（**⚠️ 2026-08-08 変更：保存先は`docs/`ではなく`docs-ignore/`。`docs-ignore/`はGit管理対象外。このリポジトリはPublicなため、レビュー前の作業記録をデフォルトで非公開にする構造にしている**）

4. 今日の日付（YYYY-MM-DD）で `docs-ignore/changelog/` 内に既存ファイルがあるか確認する
   - **注意**: Bash の `ls` で確認すること（Glob はドットファイルを正しく扱えないため）
   - 同日付のファイルが存在する場合は追記する

5. `template.md` の構造に従い変更ログを生成する：
   - **既存ファイルなし** → `YYYY-MM-DD.md` として新規作成
   - **既存ファイルあり** → ファイル末尾に `---` 区切りで追記

6. 作成・更新したファイルのパスをユーザーに報告して完了

## Git管理対象（`docs/`）へ昇格させる場合

内容を確認し、公開して差し支えないと判断できた場合のみ、以下で昇格できる（フォルダ構造は`docs-ignore/`と`docs/`で同一なので、対応パスへの移動だけで済む）。

```bash
mv docs-ignore/changelog/<ファイル名>.md docs/changelog/<ファイル名>.md
```

判断そのもの（安全かどうか）は自動化しない。人が確認するか、privacy-auditor相当のチェックを通してから昇格すること。
