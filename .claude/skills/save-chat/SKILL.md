## AIとのチャット履歴をMarkdownとして保存する。TRIGGER: 「チャット履歴を保存」「会話を記録」「議論をまとめて保存」「〜記録して下さい」「このやり取りを残して」と言ったとき。SKIP: 記録する価値が低い単純なQ&Aのとき

## 実行手順

1. `$ARGUMENTS` があればトピック名として使用する。なければ会話内容からトピックを推定する

2. 会話の内容を以下の構造でMarkdownにまとめる：

   ```markdown
   # {トピック名}

   - **日時**: YYYY-MM-DD
   - **参加者**: ユーザー, Claude

   ## 背景・目的

   {この会話が始まった経緯・解決したい課題}

   ## 議論の要点

   ### {論点1}

   - **ユーザーの意見/質問**: {要約}
   - **AIの提案/回答**: {要約}
   - **結論**: {合意した内容}

   ### {論点2}
   ...

   ## 決定事項

   - {決定1}
   - {決定2}
   ...

   ## 未決事項・次のアクション

   - [ ] {TODO1}
   - [ ] {TODO2}
   ...
   ```

3. 要約のルール：
   - 会話の全文転記ではなく、要点を構造化して記録する
   - 意思決定の根拠（なぜその選択肢を選んだか）を必ず含める
   - 技術的な詳細は必要最小限に留め、設計判断の理由を重視する
   - 却下された選択肢とその理由も記録する（後から「なぜそうしなかったか」がわかるように）

4. 保存先を決定する：
   - プロジェクトディレクトリ内に `docs-ignore/chat-logs/` がなければ作成する（**⚠️ 2026-08-08 変更：保存先は`docs/`ではなく`docs-ignore/`。`docs-ignore/`はGit管理対象外。このリポジトリはPublicなため、レビュー前の作業記録をデフォルトで非公開にする構造にしている**）
   - ファイル名: `{YYYY-MM-DD}-{トピック名のkebab-case}.md`
   - 同日・同トピックのファイルが既存の場合は末尾に連番を付与する（例: `-2`）

5. ファイルを書き出し、保存先パスをユーザーに報告する

## Git管理対象（`docs/`）へ昇格させる場合

内容を確認し、公開して差し支えないと判断できた場合のみ、以下で昇格できる（フォルダ構造は`docs-ignore/`と`docs/`で同一なので、対応パスへの移動だけで済む）。

```bash
mv docs-ignore/chat-logs/<ファイル名>.md docs/chat-logs/<ファイル名>.md
```

判断そのもの（安全かどうか）は自動化しない。人が確認するか、privacy-auditor相当のチェックを通してから昇格すること。
