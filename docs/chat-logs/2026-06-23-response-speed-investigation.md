# 回答生成速度の調査と改善方針

- **日時**: 2026-06-23
- **参加者**: ユーザー, Claude

## 背景・目的

プロトタイプの動作確認で `ask` コマンドの回答に数分かかることが判明。Ollamaのログを基に原因調査し、改善策を検討する。

## 議論の要点

### 原因の特定

- **実測データ**: 生成速度 12.2 tokens/sec（M4チップで妥当）、生成トークン数 863、所要時間 約70秒
- **結論**: LLMの処理速度自体は問題ない。回答が長すぎる（863トークン）ことが遅さの原因

### 改善策の検討

3つのアプローチを比較した：

| 方法 | 期待効果 | 採否 |
|---|---|---|
| MAX_TOKENS削減 + システムプロンプトで簡潔指示 | 25〜35秒に短縮 | 保留（現状維持） |
| GPU搭載PC / 高性能Mac | 10〜40秒に短縮 | 保留 |
| クラウドLLM（Claude API） | 7〜10秒に短縮 | 保留（マスキング精度95%検証が前提） |

### MAX_TOKENSについての確認

- MAX_TOKENSは「ここまで生成したら強制停止」する上限値
- 増やしても回答が短ければ速度は変わらない。逆に長い回答を許容するため遅くなるリスクがある
- 今回は上限1024に対し863トークンで自然終了しているため、上限に達してはいない

## 決定事項

- 現時点では修正しない（現状維持）
- 将来的な改善の選択肢として記録に残す
- クラウドLLM移行がコスパ最良だが、マスキング精度検証が先
