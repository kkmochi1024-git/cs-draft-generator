# ChromaDBのスケーラビリティと移行判断

- **日時**: 2026-06-23
- **参加者**: ユーザー, Claude

## 背景・目的

RAGのデータ量が増えた場合、ChromaDBを使い続けるべきか、別のDBサービスに移行すべきかを判断する。

## 議論の要点

### ChromaDBの限界点

- 小〜中規模（〜10,000件）は問題なし
- 大規模（10,000〜100,000件）で検索速度が低下し始める
- 超大規模（100,000件〜）でマルチユーザー・同時書き込みが非対応のため移行検討

### 想定規模の試算

- 1日30〜50件のメール × 2〜3チャンク = 1年で30,000〜50,000チャンク
- **2〜3年はChromaDBで運用可能**

### 移行先候補（必要になった場合）

- **Qdrant**: ローカル動作可、高速、本番実績多い（無料）
- **Pinecone**: フルマネージド（有料・従量課金）
- **pgvector**: PostgreSQL拡張、既存RDBに統合可能（無料）

## 決定事項

- 現時点ではChromaDBのまま運用する（移行しない）
- 設計上の備えは済んでいる（IndexService/QueryServiceがChromaDBを内部に隠蔽しており、移行時は2ファイルの変更のみ）
- 検索速度に不満が出始めたタイミングで移行を検討する

## 未決事項・次のアクション

なし（検索速度の問題が顕在化するまで現状維持）
